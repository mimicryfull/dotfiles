# ⚙️ Dotfiles

Мої персональні конфігурації для Linux (Zed Editor, VS Code / Code - OSS, кастомна тема **Katani Dark** тощо).

Завдяки **символічним посиланням (symlinks)** конфігурації прив'язані напряму до цього репозиторію:
- Будь-які зміни в редакторах одразу записуються у файли в репозиторії.
- Будь-які зміни в репозиторії миттєво застосовуються в системі.

---

## 🚀 Швидкий старт (на новому комп'ютері чи системі)

1. Клонуйте репозиторій у будь-яку зручну папку (наприклад, `~/dotfiles`):
   ```bash
   git clone https://github.com/mimicryfull/dotfiles.git ~/dotfiles
   cd ~/dotfiles
   ```

2. Запустіть встановлення:
   ```bash
   ./install.sh
   # або через make:
   make install
   ```

Скрипт автоматично:
- Створить бекапи ваших старих файлів (якщо вони були) у `~/.dotfiles_backup/`.
- Створить символічні посилання на конфіги Zed, VS Code / Code - OSS, кастомну тему `katani-theme` та інші конфіги.
- Нічого не зламає і не перезапише без бекапу.

---

## 🔄 Як працює синхронізація

Оскільки файли налаштувань у вашій системі є симлінками на файли в цьому репо:
1. Ви змінюєте тему, комбінації клавіш чи налаштування прямо в інтерфейсі **Zed** або **VS Code** (або у файлах `~/.config/zed/...`).
2. Файл оновлюється **одразу в середині `~/dotfiles`**.
3. Щоб зберегти зміни на GitHub:
   ```bash
   ./install.sh sync "Оновив тему"
   ```
   *або стандартними командами git:*
   ```bash
   cd ~/dotfiles
   git status
   git commit -am "Оновив тему"
   git push
   ```

---

## ➕ Як додати новий конфіг у dotfiles

Якщо ви хочете додати налаштування нової програми (наприклад, Kitty, Alacritty, zshrc, gitconfig):

```bash
# Додати конфіг з ~/.config/
./install.sh add ~/.config/kitty

# Додати dotfile з домашньої папки
./install.sh add ~/.zshrc
```

Скрипт сам:
1. Перенесе конфіг усередину `~/dotfiles`.
2. Створить на його місці правильний symlink.
3. Підкаже команду для `git commit`.

---

## 📋 Корисні команди

| Команда | Опис |
|---|---|
| `./install.sh` | Встановити / перевірити всі симлінки |
| `./install.sh status` | Перевірити статус симлінків та `git status` |
| `./install.sh add <шлях>` | Перенести конфіг у репозиторій і створити симлінк |
| `./install.sh sync [повідомлення]` | Закомітити всі зміни та запушити на GitHub |
| `./install.sh unlink` | Прибрати симлінки та відновити звичайні локальні копії |
| `./install.sh --dry-run` | Тестовий запуск без внесення реальних змін |

## 🗂 Структура репозиторію

```text
dotfiles/
├── .config/
│   ├── vscode/
│   │   ├── extensions/
│   │   │   └── katani-theme/    # Кастомна тема для VS Code
│   │   └── settings.json        # Налаштування VS Code / Code - OSS
│   └── zed/
│       ├── themes/
│       │   └── katani-dark.json # Тема Katani Dark для Zed
│       └── settings.json        # Налаштування Zed Editor
├── .zed/
│   ├── debug.json               # Завдання дебагу
│   └── tasks.json               # Завдання збірки / запуску (CMake/Cargo)
├── install.sh                   # Головний менеджер симлінків та конфігів
├── Makefile                     # Швидкі шорткати для make
└── README.md
```
